Creatiwity Incubator · planche design v0.3 · open source

Ramure

Viewer git de bureau (Tauri · Rust · Vue) centré sur un commit graph très lisible. Les gestes (glisser, menu, palette) produisent des commandes git natives, copiées (niveau 0) ou exécutées dans votre terminal (niveau 1). Ramure ne modifie jamais le dépôt lui-même.

Thème des maquettes
Dépôt d'exemple : sherpaLigne : 28 px (compact 22 px)Lanes : 16 pxSpec : spec-ramure.md · Lisibilité : ux-graph.md

Le graph est l'écran

Refs, graph, messages : trois lectures séparées, messages tous alignés.

Dire ce qui va se passer

Chaque geste aboutit à une commande expliquée, avec l'aperçu du résultat.

Toujours une sortie

Chaque commande est livrée avec sa commande d'annulation, en sha explicites.

Git natif, rien d'autre

Pas de service externe, pas de réseau, pas de profil : on lit la config git.

Lisibilité : v0.1 contre v0.2

Mêmes 10 commits. Les repères rouges marquent le début de chaque message en v0.1 ; la ligne verte montre le bord unique en v0.2. Détail des principes et sources dans ux-graph.md.

  • D1Messages alignésLe graph sépare le « où » (refs) du « quoi » (messages). L'œil balaie un bord gauche unique (F-pattern).
  • D1Pastille près de son nœudAlignée à droite et reliée par un trait (proximité, continuité).
  • D2Graph de largeur constanteCalculée sur tout l'historique : le bord des messages ne bouge pas au défilement.
  • D4Couleur focusVives : ma branche et sa base. Les autres désaturées, arc-en-ciel en option.
  • D5Premiers mots porteurs de sensType en sous-colonne, merges raccourcis et atténués.
  • D6Moins d'encre répétéeDate seulement au changement de jour, sha masqué, auteur répété atténué.

Pourquoi pas git rebase develop ? Les 2 anciens commits de develop seraient rejoués sur leur nouvelle version. S'ils ont été modifiés pendant le rebase de develop, cela produit des conflits sans raison.

  • Détection : reflog de la base (merge-base --fork-point) croisé avec l'équivalence de patchs (git cherry).
  • Les anciens commits restent affichés en pointillé, avec le sha de leur nouvelle version.
  • Geste manuel : sélectionner une plage (clic puis ⇧clic) et la glisser sur la nouvelle base.
  • Pile feat/a ← feat/b : Ramure propose --update-refs pour tout déplacer d'un coup.
  • Quand la commande est exécutée, le watcher la détecte et affiche l'annulation (planche J).
  • Si une ref bouge avant l'exécution, la fiche passe « périmée » et propose de régénérer.

  • Chaque intégration déclare ses capacités ; l'UI n'affiche que ce qui marche.

F

Drag & drop

On attrape une pastille, les cibles valides s'éclairent et l'action par défaut s'écrit sous le curseur. Au lâcher, le menu classe les actions et affiche la commande ; choisir une action ouvre sa fiche, ↵ copie directement.

git rebase mainAnnuler ensuite : git reset --keep a41c9e2⌥ pour copier⌥ : copieDétailsExécuter dans iTerm2 ↵Copier ⌥↵
  • Branche → branche : rebase, merge dans un sens ou l'autre, fast-forward si possible.
  • Branche → commit : rebase sur ce commit, reset à ce commit.
  • Plage de commits → base : rebase --onto.
  • Commit(s) → branche : cherry-pick. Branche → sa distante : push force-with-lease si divergente.
  • Si un checkout est nécessaire, la commande l'enchaîne avec && et le libellé le dit.
  • esc annule le glisser à tout moment.
